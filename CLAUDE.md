# CLAUDE.md — rqaem

R package implementing the recurrence quantification analysis (RQA) of
fixation sequences from Anderson, Bischof, Laidlaw, Risko & Kingstone
(2013), with a tidy data-frame workflow, bootstrap significance testing,
and radius selection. Ports the reference Python implementation
(`Rqa.py`, `RqaDur.py`) at bit-for-bit parity.

## Non-negotiable conventions

- **Bit-for-bit parity.** All `rqa()` outputs must match the Python
  fixtures in `inst/extdata/python_fixtures.json` at `tolerance = 1e-8`.
  If you change behaviour, regenerate fixtures and document the change.
- **Pure R, no Rcpp.** Inner loops stay in R until someone shows a
  real-world fixation sequence (>5000 points) where it actually matters.
- **Sparse recurrence matrices.** Use `Matrix::sparseMatrix` for `recmat`
  when `n >= 64`; dense `matrix` below that. Don't return a dense matrix
  for long sequences — it blows up RAM.
- **ggplot2-only plotting.** No base R plotting calls anywhere. Plot
  functions return `ggplot` objects.
- **No heavy CV dependencies.** Connected-components labelling for the
  clusters metric is hand-rolled (~25 lines, 8-neighbour). Don't pull in
  `imager` or `EBImage`.
- **Tidy-eval for `rqa_by()`.** Use `rlang::enquo()` / `{{ }}` for the
  column args; return a tibble.
- **License: MIT.** Cite the 2013 paper in `DESCRIPTION`'s `Authors@R`
  and in `inst/CITATION`.

devtools::document()    # after touching roxygen comments
devtools::check()       # before commits and at milestone boundaries

## Parity test pattern

The headline correctness guarantee. See PLAN.md §6 for the full strategy.

- Reference fixtures live at `inst/extdata/python_fixtures.json`.
- They are regenerated by `python data-raw/make_python_fixtures.py`
  (the script imports the unmodified `Rqa.py`; the JSON is the
  committed truth).
- Each test in `tests/testthat/test-rqa.R` loads a named case, calls
  `rqa()`, and uses `expect_equal(..., tolerance = 1e-8)` on every
  scalar metric. Recurrence matrices are compared structurally.
- If you change `rqa()` and the parity tests fail, the default response
  is **fix `rqa()`**, not regenerate the fixtures. Regeneration is only
  appropriate for documented deviations — see below.

## Deviation policy

Sometimes the originals are themselves buggy or inconsistent with the
paper (e.g. Python `RqaDur` computes `corm` even when `nRec == 0`;
MATLAB returns early). When that happens:

1. Implement the paper-correct behaviour in R.
2. Pin the new R behaviour in `tests/testthat/test-deviations.R` with a
   comment citing the paper page / equation.
3. Note the deviation in `NEWS.md` under the relevant release.
4. Mention it in the function's roxygen `@details`.

Do not silently match the originals when they disagree with the paper.

## What NOT to do yet (pre-M7)

- Don't write plotting code until M7. Mocked plot calls in vignettes are
  fine; functions in `R/plot.R` are not.
- Don't optimise. Get correctness first; the parity tests give you a
  trustworthy baseline to optimise against later.
- Don't add CRA / cross-recurrence — it's v0.2+ work (PLAN.md §3
  "Future releases").
